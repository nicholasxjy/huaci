# 划词翻译：第一版需求与实现方案

状态：第一阶段已实现（代码见 `Sources/`）。后续决定移除内置服务，只保留个人 API 设置；下文中内置服务、邀请码、费用与额度相关内容（含第二阶段）不再实施。第三阶段的签名、公证和朋友设备实测尚未进行。构建方式见 [README](../README.md)。

## 目标

为自己和少量朋友制作一个 macOS 应用：在其他应用中选中文字，按快捷键，在鼠标附近查看翻译；单词显示词典式信息，句子与段落显示译文。支持内置 OpenAI 服务和个人 API 配置。

以下内容来自需求访谈。

## 建议的实现默认值

以下是实现建议，区别于用户已明确选择的需求。可以在开发过程中根据实际验证调整。

- 使用 SwiftUI 构建设置、历史和生词列表，使用 AppKit 实现浮窗、应用状态及系统集成。
- 应用常驻菜单栏，按快捷键时显示翻译浮窗；历史、生词与设置通过菜单栏打开。
- 默认快捷键为 `Control + Option + T`，允许修改；注册失败时显示冲突提示。
- 最低系统版本建议为 macOS 13；发布前按朋友的实际设备核实兼容性。
- 历史与收藏使用本地 SQLite 存储；API Key 和邀请码使用 macOS Keychain 保存。
- 单词发音先使用系统朗读。OpenAI 提供释义和例句等内容，结果按词典形式展示；缺失或不确定的音标与词性允许留空。
- 内置服务建议使用 Cloudflare Workers + D1，负责 OpenAI 调用、邀请码、额度与费用记录。客户端通过 HTTPS 访问该服务。
- OpenAI 模型在服务端配置；先用代表性单词、中英句子和长段落评测，再确定默认模型。
- 个人 API 模式第一版支持 OpenAI 兼容接口。其他接口协议需要另做适配。
- 翻译窗口提供复制译文、朗读单词和收藏操作。
- 历史与生词只在本机保存，提供单条删除与清空入口。

## 核心使用流程

### 首次使用

1. 启动应用，在菜单栏出现入口。
2. 选择内置服务或个人 API。
3. 内置服务输入邀请码；个人 API 配置服务地址、Key 和模型。
4. 在首次使用取词功能时说明用途，并引导开启 macOS 辅助功能权限。
5. 配置完成后，在其他应用选中文字并按快捷键。

个人 API Key 只保存在本机，直接用于访问用户选择的服务地址。内置 OpenAI Key 仅由服务端保存。

### 快捷键翻译

1. 记录当前前台应用、鼠标位置与请求标识。
2. 尝试读取当前聚焦元素的选中文字。
3. 读取失败时尝试复制取词；未取得有效文字则提示重新选中，不提交翻译请求。
4. 判断原文语言和内容类型，确定翻译方向；设置中的语言规则优先。
5. 在鼠标附近显示浮窗和加载状态，位置保持在当前屏幕可见范围内。
6. 使用当前配置的翻译服务请求结果。
7. 显示单词信息或段落译文，成功结果写入本地历史。
8. 支持复制、朗读、收藏、Esc 关闭和点击外部关闭。

连续触发快捷键时以最新一次请求为准，旧结果不得覆盖新浮窗。关闭浮窗时取消仍在等待的请求；服务端已经开始的调用可能仍产生费用，应按实际返回的用量记账。

### 单词与段落

单词展示包含原文、译文、词性、可用音标、例句及朗读操作。词典式结果由模型生成，输出应遵循结构约束；不确定的信息允许缺省。

句子与段落展示原文及译文，保留段落结构，较长内容可滚动查看。混合语言、短语和专有名词需要纳入评测，避免只按字符数判定内容类型。

## 跨应用取词与剪贴板恢复

跨应用支持需要经过实测。部分应用的自绘界面、远程桌面或特殊文本控件，可能既不提供辅助功能选区，也不能正常复制，因此不能保证所有应用和所有位置都可取词。

实现应满足以下条件：

- 辅助功能接口成功读取时，不操作剪贴板。
- 复制前保存可恢复的剪贴板内容与版本，支持多条目和多个数据类型。
- 只有剪贴板版本发生预期变化，且得到有效文本时，才把复制结果作为原文；不能读取旧剪贴板冒充当前选区。
- 复制期间前台应用改变时，终止这次取词，避免把复制命令发送到错误的应用。
- 取词完成后，仅在剪贴板仍是本次复制产生的版本时恢复；用户在此期间复制了新内容，应保留新内容。
- 剪贴板内容无法可靠保存时，终止自动复制并给出可理解的提示。
- 没有选区、复制无效、权限未开启或操作超时，都应返回明确状态，避免提交空文本。

## 内置服务与邀请码

每位朋友使用独立、随机生成的邀请码。同一个邀请码在多台设备使用时共享额度。邀请码验证通过后保存在本机 Keychain，服务端支持单独停用并记录其调用用量。

服务端负责：

- 持有 OpenAI Key，配置允许使用的模型及最大输出长度。
- 验证邀请码的有效性，服务端保存邀请码的哈希。
- 在调用 OpenAI 前验证原文长度、每日额度及共享预算。
- 对单个邀请码进行并发控制与速率限制。
- 对失败、超时、停用、额度用尽返回可区分的状态。
- 用于费用管理的记录只包含身份标识、时间、模型、用量和状态；默认不记录原文、译文与个人 API Key。

第一版管理功能可以通过受保护的管理接口或运维命令完成，不增加面向朋友的账号系统和管理后台界面。

## 费用与额度

共享总预算按月配置，每个邀请码的调用额度按日配置；单次输入长度和最大输出 token 数也应可调整。

用户尚未指定预算数值。部署时必须明确配置这些数值，配置完成后才能启用内置服务。个人 API 模式仍可独立使用。

费用控制需要在请求前生效：按输入与最大输出预留预算，完成后根据 OpenAI 返回的用量结算，释放未用部分。额度检查与预留必须使用原子操作，避免同时发起的请求突破上限。调用账本按请求标识处理，避免同一结果重复记账。

成本估算使用所选模型的价格配置，按供应商结算币种计算。该上限管理的是本服务记录的调用，估算费用可能与 OpenAI 最终账单存在差异；其他应用使用同一 Key 的费用也不在此账本中。

日/月周期按服务端统一时区计算，客户端显示具体的额度恢复时间。调整后的配置在新请求上生效，停用的邀请码不能继续发起新调用。

## 分阶段实现

### 第一阶段：本机完整使用链路

- 菜单栏入口、首次配置、权限引导和可配置快捷键。
- 辅助功能取词、剪贴板回退与有条件恢复。
- 鼠标附近浮窗、单词/段落展示、复制与系统朗读。
- 个人 API 配置、语言规则、加载/错误/取消处理。
- 本地历史、收藏、搜索与删除。

完成标准：配置个人 API 后，可以在目标应用中选中文字，通过快捷键获得翻译，保存历史并收藏单词。

### 第二阶段：免配置的共享服务

- OpenAI 服务端代理和可配置模型。
- 邀请码生成、验证、停用与本机保存。
- 每日额度、共享预算、并发与输入长度控制。
- 内置服务配置和客户端状态展示。

完成标准：配置服务端 OpenAI Key、预算和额度并部署后，朋友只需输入邀请码即可使用；停用和限额在调用前生效。

### 第三阶段：朋友安装与实测

- 打包 macOS 应用，准备签名、公证与安装说明；签名和公证依赖 Apple 开发者账号及证书。
- 在朋友实际使用的 macOS 版本和处理器架构上验证安装、首次配置与权限引导。
- 以实际测试结果维护应用兼容性清单。
- 调整默认模型、窗口尺寸、响应速度和错误提示。

完成标准：朋友能独立安装并完成首次翻译；目标应用中的取词、剪贴板和翻译流程通过实测。

## 验收重点

1. 在 Safari/Chrome、Preview 的可选中文本 PDF、至少一种聊天工具和代码编辑器中验证取词，并注明测试版本。
2. 有选区、无选区、中文、英文、其他外文、混合语言、单词、短语与长段落均有明确行为。
3. 复制失败不能误翻旧剪贴板；剪贴板原有图片和多类型内容能够恢复；用户新复制的内容不会被覆盖。
4. 连续请求、切换前台应用、关闭窗口和网络超时不会显示错位结果。
5. 无效/停用邀请码、额度耗尽、预算耗尽和服务故障能显示可理解的状态。
6. 多个并发请求不能越过预算与邀请码额度；调用结果不得重复记账。
7. 历史与收藏在应用重启后保留，删除与清空正常；个人 Key 不出现在历史、日志和内置服务请求中。
8. 鼠标靠近屏幕边缘或使用多显示器时，浮窗完整可见。
